# Contributing

This is a source-available personal-use project, not an open-source project. Read [LICENSE](LICENSE) and [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) before proposing a change. GitHub's applicable repository/fork permissions remain intact; they do not grant unrestricted resale or service rights.

Open an issue with the problem, expected behavior, release/commit and a small fictional reproduction. Never include API credentials, account exports, research documents without redistribution permission, or real trade instructions. Use the [security reporting route](SECURITY.md) for sensitive vulnerabilities.

Before submitting a patch, confirm you have authority to contribute it, identify any third-party material and retain its notices. Contributions are subject to the repository's applicable license and GitHub contribution terms unless separately agreed; do not submit work under incompatible terms. Propose licensing questions before contributing. No copyright assignment is implied merely by contributor credit.

Keep changes focused and preserve the distinction between paper analysis, read-only data access and human-operated execution. Add meaningful tests for financial calculations, normalization, persistence and failure handling. Never loosen execution confirmations or claim authenticated acceptance from fixtures.

Run:

```text
python scripts/release.py --check
```

Describe what changed, why, the relevant validation and any remaining limits. Contributions do not require a funded brokerage account, real trades or paid subscriptions. The maintainer may decline changes and does not promise a support schedule.
