# F&O analytics

`scripts/fno.py` analyses NSE index and stock options and futures. It never places orders.

## Commands

```text
python scripts/fno.py chain NIFTY --summary
python scripts/fno.py chain NIFTY
python scripts/fno.py chain NIFTY --no-compare --no-vix
python scripts/fno.py chain BANKNIFTY --expiry 2026-12-29 --strikes 8
python scripts/fno.py chain RELIANCE --format json --out reports/reliance-chain.json
python scripts/fno.py expiries BANKNIFTY                 # each expiry labelled weekly/monthly, moved ones flagged
python scripts/fno.py chain NIFTY --weekly --summary      # nearest weekly; --monthly for the nearest monthly
python scripts/fno.py payoff NIFTY --leg SELL:CE:25800:1 --leg BUY:CE:26000:1 --leg SELL:PE:25000:1 --leg BUY:PE:24800:1 --chart reports/condor.svg
python scripts/fno.py payoff NIFTY --leg SELL:CE:25800:1 --leg BUY:CE:26000:1 --summary
python scripts/fno.py payoff NIFTY --leg BUY:FUT::1 --leg SELL:CE:25800:1
python scripts/fno.py payoff BANKNIFTY --leg BUY:PE:ATM-1:1 --leg SELL:PE:ATM-1-500:1 --summary   # bear put spread one strike below ATM, 500 wide
python scripts/fno.py payoff NIFTY --leg SELL:CE:ATM:1 --leg SELL:PE:ATM:1 --leg BUY:CE:ATM+200PTS:1 --leg BUY:PE:ATM-200PTS:1 --summary   # iron fly
python scripts/fno.py grid NIFTY --structure fly --summary            # iron fly at the default wing widths (one row each)
python scripts/fno.py chain NIFTY --input trader/nifty-chain.json
python scripts/fno.py chain NIFTY --input trader/nifty-chain.json --previous-date 2026-11-17
python scripts/fno.py grid BANKNIFTY --structure condor --monthly   # short strikes at several deltas, no choice made (wings 500: the BANKNIFTY default)
python scripts/fno.py grid NIFTY --structure strangle --weekly
python scripts/fno.py grid NIFTY --structure spread --width 200 --side put --deltas 0.30,0.20,0.10
python scripts/fno.py grid BANKNIFTY --structure condor --width 500 --monthly --row 4 --chart reports/bn-row4.svg   # one row's full payoff + chart
python scripts/fno.py grid BANKNIFTY --structure condor --width 500 --monthly --row 4 --summary                     # one row, short form
python scripts/fno.py payoff NIFTY --leg SELL:CE:25800:1 --summary --no-margin   # skip the ~10 MB NSE SPAN file
python scripts/fno.py payoff --leg SELL:CE:25800:1 --summary     # no underlying: inferred from the strike (stated in the output)
python scripts/fno.py chain 25800CE --summary                     # same inference; adds a line for that contract
```

Common options: `--expiry` (default nearest live expiry) or `--weekly` / `--monthly` (nearest expiry of that type; when the data lists one expiry per month, as for BANKNIFTY, FINNIFTY and MIDCPNIFTY since NSE dropped their weeklies in Nov 2024, `--weekly` uses the nearest monthly and the first lines say so — exit 0), `--no-live` (skip the NSE holiday list and the live index level: offline labels only), `--date` (bhavcopy trading day; default latest published), `--rate` (risk-free assumption, default 6.5%), `--format markdown|json`, `--out NEW_FILE`. Payoff legs are `SIDE:TYPE:STRIKE:LOTS[:PREMIUM]`; the premium defaults to that contract's traded close. Lots are multiplied by the exchange lot size from the data.

`chain` options:

- `--summary`: a short answer-first block (about fifteen lines, in plain words: no model or file names — the futures-implied level, Black-76 and the NSE Clearing file names stay in the full report — ranges that say what they cover — "covers the rest of today, about 4h 56m of trading, plus tomorrow" — and participant OI as "FIIs … net short 116,830 calls (down 69,819 on the day)"): the END-OF-DAY line when the market is open, any selection or underlying note, expiry and its type (plus an "Expiry:" line, naming the NSE holiday, when it moved or the underlying has no weeklies), data date, spot (dated close) and the live level when open, PCR (OI) and max pain with their day-over-day change, ATM IV and its change, expected move and 68% implied range to expiry, the dated session ranges (the session after the data date; "tomorrow" from the live level when today's session has started), the named strike's line when a strike was given, India VIX, the biggest call and put OI walls, the day's net OI change, and participant-wise OI (FII/Client index futures long %, net and day change; FII index options net calls/puts). It ends with a **Next session** block: the dated 1-SD range to the next session's close (during market hours from the live level, sized with the same 'now' ATM IV the summary quotes, labelled) and the OI walls near spot. Max pain gives its distance from the close and from the live level; the expected-move line labels the straddle as a multiple of the 1-SD move ("≈ 0.8 SD"; an ATM straddle is worth about 0.8 SD when options are fairly priced). With `--format json` it prints the same fields as `fno_chain_summary_v1`. The full report stays the default.
- `--no-compare`: skip the previous trading day's bhavcopy (one fewer ~1.5 MB download).
- `--previous-date YYYY-MM-DD`: compare with the bhavcopy on or before this date instead of the trading day before the data date. It must be before the data date. With `--input` the comparison runs only when this is given; otherwise the report says it was skipped.
- `--strikes N` (strikes each side of ATM), `--no-vix`.

**Relative strikes** (round 8): a leg's strike can be `ATM`, `ATM±N` (N strike steps), `ATM±N±M` (N steps, then M points) or `ATM±MPTS` (points). ATM is the listed strike (with both a call and a put) nearest the level a trader sees — the live or closing level the report quotes after the data date, else the chain's spot (the last close) — and the step is the most common gap between the listed strikes nearest the forward. The report's first lines print what each one resolved to ("**Strikes:** ATM 64,600 = the strike nearest spot 64,635.20 (the Fri 20 Nov close); strike step 100: ATM-1 → 64,500 PE, ATM-1-500 → 64,000 PE"; JSON `report.strike_resolution`). A plain number after ATM is always strike steps; a leg that resolves to an unlisted strike stops with the nearest listed strikes and that reminder. Relative legs need the underlying named.

`payoff` options: `--leg` (repeatable), `--range` (percent either side of spot, default 8), `--chart NEW.svg`, `--charges CARD.json` (default `assets/charges.example.json`), `--no-margin` (skip the SPAN file), `--held` (you already hold these legs from the last close: the summary adds their model P&L now; the full report always has it), and `--summary`. **During market hours (EOD data, live level available) the summary leads with "If placed now — model estimate"**: a table with, per leg, the premium re-priced now (≈) next to the close's, then net premium, maximum profit and loss, breakevens (with the chance of finishing above each), probability of profit and chance of the maximum loss — all after costs — plus the indicative margin and return on margin, in an "If placed now (estimate)" column beside an "At the <day> close" column; then P&L at expiry at ±1/2/3 SD, overnight gaps and the 68% range for a trade placed now, how "now" was estimated, the margin line, and, with `--held`, the model P&L now for a position already opened at the close — valued on the same snapshot prices as the "If placed now" column (premium at the close minus premium now, × units), so the two cannot disagree; only without a snapshot is it the close-IV model at the live level, labelled "IVs held at the close". Outside market hours the summary is the end-of-day form: net premium before and after entry charges, maximum profit and loss after costs ("unlimited" when uncapped), breakevens after costs with the probability of finishing above each, probability of profit after costs (skew, with the flat-ATM figure alongside when different), chance of the maximum loss, expected value at implied prices, P&L at ±1/2/3 SD at expiry, an overnight-gap scenario, the 68% range, T+0 at the live level (otherwise labelled as the close it is priced at), and the indicative margin with return on margin. JSON schema `fno_payoff_summary_v1` (new keys `placed_now`, `margin`, `return_on_margin`, `eod_outcome`). The full report puts the same "If placed now" section first and the end-of-day report under "At the <day> close (end-of-day data, for reference)".

`grid SYMBOL --structure fly [--width N]` (round 8) is the iron fly: sell the ATM call and put (ATM as for relative strikes) and buy the traded call and put nearest `width` points out, one row per width — defaults NIFTY 100/150/200/300, BANKNIFTY 300/500/700/1000, FINNIFTY 100/150/200/300, MIDCPNIFTY 50/75/100/150 points, other underlyings 2/3/4/6 strike steps; `--width N` gives one row. The header names the widths and the ATM ("wings 100, 150, 200 and 300 points from the ATM 25,800 (default for NIFTY; one width with --width)"); `--row N` prints that row's payoff ("Grid row 3 (iron fly, wings 200 points from the ATM 25,800)").

`grid SYMBOL --structure condor|strangle|spread [--width N] [--side call|put|both] [--deltas 0.3,0.2,0.1] [--expiry/--weekly/--monthly]` (`--width` defaults to NIFTY 100, BANKNIFTY 500, FINNIFTY 100, MIDCPNIFTY 50 points and two strike steps for stocks and other indices; the header then says "wings 500 points (default for BANKNIFTY; change with --width)"; every argument is checked before any download, so a bad `--deltas`, `--row`, date or existing output file fails at once): when the user names a structure but no strikes ("Bank Nifty iron condor?"), this lists rows of short strikes at several deltas (default 0.35 down to 0.05), each with its SD distance from the forward and the long wings `--width` points further out, with credit after entry charges, maximum profit and loss after costs, breakevens after costs, probability of profit (skew; flat in brackets), chance of the maximum loss, indicative margin, return on margin (max profit after costs ÷ margin) and the P&L at expiry at −2 / −1 / +1 / +2 SD after costs — per 1 lot, rows numbered `#`. During market hours the main table is "If placed now — model estimate": strikes are picked by delta at the close (so `--row N` names the same legs on every run that day), then Δ, SD distance and every figure are re-computed for a trade placed now (method below); a second table gives the same strikes at the close. The summary shows each short leg's delta now (`Δ 0.47`) and marks with ⚠, plus a line per row ("⚠ Row 1: short put 61,800 is now near the money — 0.06% from live BANKNIFTY …"), any short strike within 0.5% of the live level. It shows the trade-offs and does not pick a row: present the rows, then `--row N` (same command) prints that row's full payoff report — or `--summary` for the short form — and `--chart FILE.svg` writes its chart, in one run. JSON schema `fno_grid_v1` (rows also carry `margin`, `return_on_margin`, `sd_pnl`, and `eod` during market hours; expected value stays in `ev_after_costs`).

`chain` also takes `--no-participants` (skip NSE's participant-wise OI files).

## Data

By default the script downloads NSE's public F&O bhavcopy (`nsearchives.nseindia.com/content/fo/BhavCopy_NSE_FO_0_0_0_YYYYMMDD_F_0000.csv.zip`, about 1.5 MB). It is published after the close and lists every contract with OHLC, settlement price, open interest, OI change, volume, underlying price and lot size. The script tries today and walks back over weekends and holidays. Reports are therefore **end of day**.

For live analysis, supply a chain with `--input`, for example read from the user's broker connector:

```json
{
  "schema": "fno_chain_v1",
  "underlying": "NIFTY",
  "as_of": "2026-11-18T11:05:00+05:30",
  "source": "Kite connector option chain",
  "spot": 25410.5,
  "lot_size": 65,
  "expiry": "2026-11-23",
  "rows": [
    {"type": "CE", "strike": 25400, "last": 192.3, "prev_close": 189.2, "oi": 4700000, "oi_change": 120000, "volume": 880000},
    {"type": "PE", "strike": 25400, "last": 170.1, "prev_close": 179.95, "oi": 4400000, "oi_change": 95000, "volume": 760000},
    {"type": "FUT", "last": 25438.0, "prev_close": 25415.3, "oi": 1500000, "oi_change": -20000, "volume": 90000}
  ]
}
```

OI and volume are in units (shares), as NSE reports them; reports convert to contracts using the lot size.

Other public sources (each optional; a failure is reported, never fatal):

- **NSE holiday master** (`www.nseindia.in/api/holiday-master?type=trading`, F&O list, current year only): names the holiday that moved an expiry ("moved from Tuesday 2026-11-24, NSE trading holiday (Prakash Gurpurb Sri Guru Nanak Dev)" — Guru Nanak Jayanti) and skips holidays when counting sessions. Without it the expiry note keeps "probably for a holiday — check the exchange circular" and only weekends are skipped.
- **Live index level** (Yahoo chart meta `regularMarketPrice` for `^NSEI`, `^NSEBANK`, `NIFTY_FIN_SERVICE.NS`, `NIFTY_MID_SELECT.NS`, `^NSMIDCP`, or `SYMBOL.NS` for stocks): fetched only when today's session has started and the bhavcopy is older than today, and used only if the quote is from today. Unofficial and possibly delayed; it re-centres the "tomorrow" range, re-marks payoff T+0 and drives the "If placed now" re-price (with India VIX's live quote, `^INDIAVIX`, for NIFTY). It is not a live option chain.
- **NSE Clearing SPAN files** (`nsearchives.nseindia.com/archives/nsccl/span/nsccl.YYYYMMDD.{iN,s}.zip`, ~10 MB each, payoff and grid only; skip with `--no-margin`): the indicative margin described under Method. Today's intraday files are tried newest first (missing ones cost one small 404 each), then the data date's end-of-day file.
- **Participant-wise OI** (`nsearchives.nseindia.com/content/nsccl/fao_participant_oi_DDMMYYYY.csv`, free, after the close): contracts held long and short by Client, DII, FII and Pro in index futures and index options, for the data date and the previous trading day (the day change). It covers all NSE index derivatives and expiries together, not one underlying; options are counted in contracts, not delta-weighted. FIIs often run index futures short against cash holdings, so a net short alone is not a bearish signal. The file is checked: its "as on" date must match, and participants must sum to the balanced TOTAL row.

**Live-data honesty:** when the market is open and no `--input` chain is given, the first line of every chain, payoff and grid report is "END-OF-DAY data from <day> close, N hours old; the live chain needs your broker connector (--input)". With a connector chain there is no such line. Live option prices, live OI and margins without a connector are outside what this free script can provide.

## Method

- **Forward:** taken from put-call parity at traded strikes near the money (median of up to six pairs), which absorbs dividends and carry without guessing them. If no pair traded, the spot is carried at the rate assumption, and the report says so.
- **Implied volatility and Greeks:** Black-76 on that forward (NSE options are European). IV uses traded closes only; untraded contracts carry a stale previous close and get no IV. Greeks are per unit; delta is spot delta, theta is per calendar day, and vega is per one volatility point.
- **PCR:** put OI ÷ call OI, and put volume ÷ call volume, for the chosen expiry.
- **Max pain:** the strike at which the total intrinsic value owed to option holders at expiry is smallest.
- **OI walls:** the three strikes with the most call OI at or above spot, and the most put OI at or below spot ("biggest overall"). **Near spot:** the two strikes with the most call OI above and put OI below spot inside the to-expiry 1-SD range (F·exp(−σ²T/2 ± σ√T) at the ATM IV; ±3% of spot when there is no IV or a side of the range has no strike) — the levels to quote for the next session, since the global maxima can sit several percent away (BANKNIFTY 18 Nov 2026: put walls 57k/58k/60k, 3.6–8.5% below spot). JSON `oi_walls_near` (`calls`, `puts`, `window`, `basis`). Max pain is shown with its distance from spot ("60,000 — 3.7% below spot (the Tue 17 Nov close)"; JSON `max_pain_vs_spot`).
- **Build-up:** price change and OI change per contract: long build-up (price up, OI up), short build-up (price down, OI up), short covering (price up, OI down), long unwinding (price down, OI down). The report shows signed OI changes in contracts: "OI added" rows (long and short build-up) are positive, "OI reduced" rows (short covering and long unwinding) are negative, and "not classified" holds OI change on contracts that did not trade or have no previous close. Added + reduced + not classified = the net OI change in the summary table. JSON `call_oi_breakdown` / `put_oi_breakdown` carry the same signed numbers in units (shares) with `added_total`, `reduced_total`, `unclassified` and `net`.
- **Expiry type:** worked out from the listed expiries, not a calendar of rules. In each calendar month the expiry shared with the futures contract (or, with no future, the last option expiry of the month) is the **monthly**; any other expiry in that month is **weekly**. An underlying with one expiry per month has no weeklies. The usual expiry weekday is the one most expiries follow (weeklies on that weekday, monthlies on its last occurrence in the month). With NSE's holiday list (loaded by every command unless `--no-live`), an expiry on the last trading day before an NSE holiday that falls on a weekday counts for that weekday, and is flagged **moved** from that holiday by name ("moved from Tuesday 2026-11-24, NSE trading holiday (Prakash Gurpurb Sri Guru Nanak Dev)"); a tie between two weekdays goes to Tuesday, NSE's expiry day for every equity derivative since 1 Sep 2025 (round 7: with three FINNIFTY monthlies — Mon 23 Nov, Tue 29 Dec, Mon 25 Jan — the old tie-break to Monday had called the Tuesday 'moved from Monday 28 Dec'). Any other expiry off the pattern is flagged **moved** with the date it would normally fall on — "probably for a holiday — check the exchange circular" (e.g. 26 Jan 2027 while next year's holiday list is not out). Example: BANKNIFTY's November 2026 contract expires Monday 23 Nov because Tuesday 24 Nov is a holiday; it is the monthly, not a weekly. Shown in the chain and payoff headers, the `expiries` list, both summaries and the SVG title; JSON keys `expiry_type`, `expiry_weekday`, `expiry_moved`, `expiry_usual_date`, `usual_expiry_weekday`, `has_weeklies`, `expiry_note`, `expiry_calendar`. A single-expiry `--input` chain cannot be classified and says so.
- **Expected move:** the ATM straddle price, the IV-implied one-standard-deviation move to expiry (spot × ATM IV × √T), and a 68% implied range: ±1 standard deviation of log price around the lognormal median, F·exp(−σ²T/2 ± σ√T). During market hours, when the "Now (estimate)" is available, the summary's line is re-centred on the live level: the now ATM straddle and the 68% range from the now forward and now ATM IV, labelled "from live 25,189.25 at 12:55 IST, snapshot IV" (or "IVs from the Tue 17 Nov close" without a snapshot; JSON `now_estimate.range_1sd`). The close-based figures stay in the full report, labelled "from the Tue 17 Nov close".
- **Dated session ranges** (for "kal ke liye?" / "what about tomorrow" questions): every range names its session and its centre. The first is for the session after the data date, centred on that close: centre × ATM IV × √(1/252) (about 68% of outcomes if the IV is right; implied by option prices, not a forecast). Its status says whether that session is tomorrow, today and in progress, or already closed. When that session has already started (market open, or closed today before today's bhavcopy is out), a second range runs to the close of the next session not yet started: from the live level, counting the rest of today as a fraction of a 6¼-hour session plus one session, or — without a live level — two sessions from the old close (√(2/252)). Before 09:15 on a trading day the single range is today's. Sessions skip weekends and NSE holidays. The IV is annualised on calendar time; the trading-day basis spreads weekend and holiday variance over sessions. JSON `session_ranges` (`session`, `status`, `centre`, `centre_label`, `sessions`, `rest_of_today`, `points`, `pct`, `low`, `high`) and `session` (phase, next session, data age); `one_day_move` is kept for compatibility (undated, from the close).
- **Day over day:** the previous trading day's bhavcopy is fetched (walking back over weekends and holidays, as for the main file) and the same expiry is re-analysed with the same method. Spot, PCR (OI), max pain, ATM IV and call/put OI are shown for both days with the change. If the previous file is unavailable or does not list the expiry, the report says so and continues. JSON key `day_over_day` has `status` (`ok`, `unavailable` or `skipped`), the dates and `metrics.{name}.previous|current|change`.
- **India VIX:** the close on the chain's trading date, taken from the public Yahoo one-year daily history, with its percentile and range over that history up to the date. If that date has no close (holiday or missing bar), the previous close is shown and the report says the exact date was missing. Shown for index underlyings.
- **Payoff:** P&L at expiry across ±8% of spot (wider if strikes require), breakevens, net premium, maximum profit and loss (unlimited when the payoff still slopes at the top of the range; reported at zero when the extreme happens only if the price falls to zero), and current position Greeks. The table has about 15–20 rows: evenly spaced prices across the range (rounded) plus every strike, breakeven and spot, sorted and deduplicated, each with the expiry P&L, today's (T+0) P&L and a note marking strikes, breakevens and spot.
- **Today (T+0):** the strategy's mark-to-market P&L if the underlying moved to each price now: each option leg is valued with Black-76 at its own implied volatility (from the contract's traded close, else from the leg's premium) and the current time to expiry, with the forward moved in proportion to the underlying and IV held constant; futures legs move with the underlying. It is unavailable when an option leg has no IV. The SVG chart shades profit and loss zones at expiry, marks spot and breakevens, and draws T+0 as a dashed second line with a legend.
- **Probabilities (implied by option prices, not a forecast):** risk-neutral, on the put-call-parity forward, to expiry. The headline uses **each strike's own IV (skew)**: a least-squares quadratic smile σ(x) = a + b·x + c·x², x = ln(K/F), through the traded out-of-the-money IVs (puts below the forward, calls above) within ±4 ATM standard deviations, flat beyond the fitted strikes. P(S_T > K) is minus the strike-derivative of the undiscounted Black-76 call priced on that smile: N(d2(σ(K))) − F·φ(d1)·√T·σ′(K). The slope term matters: with put skew it puts more probability above a strike than N(d2) at that strike's own IV. The flat figure (one ATM IV: N((ln(F/K) − σ²T/2)/(σ√T)), or the legs' average IV if ATM IV is missing) is shown alongside when different. With too few traded strikes either side the smile is not fitted and both columns are flat. Reported: probability of profit at expiry after and before costs, chance of the maximum loss (the probability of finishing where the gross payoff is at its floor, e.g. beyond a condor's long strikes; none for uncapped losses), the probability of finishing above each breakeven, and the 68% range. The payoff is linear between strikes (also after costs), so each probability is integrated exactly segment by segment, including beyond the plotted range. They ignore closing early.
- **Costs:** the NFO option (and future) rows of the rate card (`assets/charges.example.json`, the same card as `position_size.py`): flat brokerage per option order (percentage with a cap for futures), STT on sell premium, exchange and SEBI fees, stamp duty on buys, GST on brokerage + fees. Entry at the prices used; exit by squaring off every leg at its expiry value. Net credit/debit after entry charges; max profit/loss and breakevens after entry and exit charges. Each leg's exit at expiry costs the dearer of squaring off at its expiry value and, for an in-the-money long option left to exercise, exercise STT (0.15% of intrinsic value from 1 Apr 2026, 0.125% before; card key `stt_exercise`). STT rates (checked 21 Nov 2026 against Zerodha's charges page and the Finance Act 2026, which amended s.98 of the Finance (No. 2) Act 2004 with effect from 1 Apr 2026, per the NSE circular of 31 Mar 2026 "Changes in rates of Securities Transaction Tax"): sale of futures 0.05% (was 0.02%), sale of options 0.15% of premium (was 0.1%), options exercised 0.15% of intrinsic value (was 0.125%). The card carries the earlier rates under `stt_before` (until 31 Mar 2026), and a data date (`--date`) before 1 Apr 2026 uses them. Maximum loss after costs is the worst after-cost value at every expiry level shown — the payoff range and the ±1/2/3 SD rows — so it includes the STT on in-the-money legs and is never smaller than any row (18 Nov 2026: a Bank Nifty condor's summary said ₹10,996, taken at the long strike, while its own −3 SD row showed −₹11,152); JSON keeps the at-the-long-strike figure as `max_loss_first` and the level used as `max_loss_level`. A leg left to expire worthless saves its exit brokerage. Slippage is excluded. The card is an estimate, not a contract note.
- **Expected value at implied prices:** each option's risk-neutral expected payoff is its Black-76 value at its own IV grown at the rate, so before costs the EV is only interest on the premium (about ₹0) and after costs it is about minus the round-trip charges. It shows that the market price is fair under its own assumptions; any edge has to come from a view that differs from it.
- **Stress:** P&L after costs at expiry at the lognormal median F·e^(−σ²T/2) × e^(±kσ√T) for k = 1, 2, 3 (ATM IV) — the same basis as the 68% range, so ±1 SD are exactly its ends (grid SD columns too), and an overnight gap of ±3 one-session SD (spot·e^(±3σ/√252)) marked the next morning with one day less to expiry — IVs unchanged, and a down-gap with IVs +5 vol points — after entry charges.
- **If placed now — NSE intraday prices first:** NSE Clearing's intraday SPAN files (i2, i3, … through the session) carry the exchange's own price for every option and future at the file's creation time (`<created>`, e.g. 11:03 IST; i1 is created the evening before and carries the previous close). When the margin step has fetched such a file from today's session, at most 3 hours old, the chosen expiry is rebuilt from those prices (IV, smile, forward and ATM IV recomputed) and then moved to the live level, if that is newer, with Black-76 at each strike's snapshot IV and the time left. The heading says "estimate … from NSE's HH:MM IST intraday option prices, not live quotes". Example, 18 Nov 2026: NIFTY 25800 CE closed ₹51.45 on 17 Nov; NSE's 11:03 snapshot priced it ₹25.20 (NIFTY 25,226), where the close-IV model alone gave ≈ ₹21.65 — the snapshot captures the intraday IV rise the model cannot. **The level moves start from:** the file's index level (`<phy><p>`) and its option/futures prices are not taken at the same instant — in nsccl.20261118.i02 BANKNIFTY read 62,044.35 (the 10:59 index) while its Nov future was 61,983.40 and put-call parity gave a forward of 61,994, a level of ≈61,970 at the close's basis. Moving from 62,044 to a live 62,209 therefore under-priced calls (63200 CE ≈136 vs ≈150 on the consistent basis). The snapshot level is now the parity forward ÷ the close's carry (F/S at the close)^(T_snap/T_close); the "how" line names both levels when they differ by more than 0.01%. During market hours the chain shows the same estimate as a "Now (estimate)" line — ATM strike, ATM IV, ATM straddle and its call and put — and its summary leaves out the range for today's running session (it is from yesterday's close) and leads with the next session's dated range.
- **After the close, before the evening bhavcopy (round 6):** from 15:30 IST until today's bhavcopy is published (usually ~18:00–19:00 IST) the last bhavcopy is yesterday's, and every report says so in a bold first line. `chain` then reads NSE's public option chain for the same expiry (`https://www.nseindia.com/api/option-chain-v3?type=Indices|Equity&symbol=…&expiry=DD-Mon-YYYY`, exact pattern, fetched from NSE's www.nseindia.in API twin with no redirects and an 8 MB cap; NSE's robots.txt allows `/api/`), which must be stamped after 15:30 today. Its OI (in contracts, ×lot size to match the bhavcopy's shares), OI change, last prices and the index close become the report's data, labelled "NSE option chain, 18 Nov 15:30 close", with the expiry calendar from the last bhavcopy; the day-over-day comparison is against that bhavcopy (18 Nov 2026: BANKNIFTY PCR 1.18 vs the stale 1.34; NIFTY 0.86). Option prices there are last trades, which can differ from the bhavcopy's closing (settlement) prices. Today's participant OI file is published in the evening, so the previous one is shown, dated. India VIX uses NSE's close (Yahoo's daily bar for the day was stale, 15.52 vs 15.56). If the option chain fails, the chain falls back to the bhavcopy with "PCR, OI and max pain below are the Tue 17 Nov close — re-run after that". `payoff` and `grid` keep the "If placed now (estimate)" column, the short legs' Δ and the ⚠ near-the-money line, priced at today's NSE closing level (allIndices; Yahoo for stocks, labelled unofficial) from NSE Clearing's closing intraday file (i5, created 15:32, which carries the closing level and NSE Clearing's closing option prices; its end-of-day file's prices equal the bhavcopy's ClsPric — 17 Nov: NIFTY 25800 CE 51.45 in both, while the last trade was 45.30 — so it is used as it is, without the parity re-basing; 18 Nov: 25800 CE ₹21.00 there vs a last trade of ₹19.05 in NSE's option chain). The ended session gets no 1-SD line; the expected move and the tomorrow range are centred on today's close. A single short option whose price has moved ≥ 20% from the close leads with "Selling now would get about ₹21.00 a unit (≈ ₹1,365 for 1 lot of 65; estimate) — not the ₹51.45 of the Tue 17 Nov close".
- **If placed now (model estimate, fallback):** with no fresh intraday snapshot (`--no-margin`, file missing, older than 3 hours), when the data is end of day, the market is open and a live level was fetched, every traded option of the expiry is re-priced with Black-76 at the live level with its own IV from the close and the time left now; the forward moves with the underlying (F_now = S_live × (F/S)^(T_now/T)). For NIFTY the IVs are scaled by India VIX's move today (live ÷ previous close from the public Yahoo quote, used only when the data is the previous session); other underlyings keep the close's IVs, and the text says which. Premiums are rounded to the 0.05 tick and the chain is re-analysed with the same method, so premium, maximum profit/loss, breakevens, probabilities, costs, stress and EV for a trade placed now come from the same code as the end-of-day figures. It is a model, not live option quotes (no bid/ask, no intraday skew change); the output says so and asks to check the broker's chain. Grids pick strikes by delta at the live level.
- **Margin (indicative):** `scripts/fno_margin.py` reads NSE Clearing's free SPAN® risk-parameter file — `nsearchives.nseindia.com/archives/nsccl/span/nsccl.YYYYMMDD.iN.zip` (intraday files; i1 is published the evening before from the close) or `nsccl.YYYYMMDD.s.zip` (end of day), about 10 MB zipped. **Which file, by time of day:** before the open and during the session margin is computed on the begin-of-day parameters (below); after the 15:30 close on a trading day it is computed on that day's closing intraday file (created 15:30 or later, i5 at 15:32 on 18 and 19 Nov 2026), which also prices 'if placed now', with exposure on today's close (the next session's previous close) — reconciled against Zerodha's SPAN calculator on 19 Nov 2026 at 18:04 IST with `nsccl.20261119.s.zip` already published: FINNIFTY 28300 short straddle SPAN ₹1,53,376 (closing file ₹1,53,375.60; `s` file ₹1,55,060.40; the previous day's file ₹1,73,795.40), NIFTY 25300/25500 bull call spread ₹0 (all files), BANKNIFTY 61500/62000/64000/64500 condor ₹13,649.50 (₹13,649.40; `s` ₹13,987.20) and naked short NIFTY 25800 CE ₹1,33,085.75 (₹1,33,086.20; `s` ₹1,34,067.05); Zerodha's net option values equal the closing file's prices. Re-checked at 22:22 IST, after the next session's i1 (21:15, identical to the `s` file) was out: Zerodha still matched the closing file on all four, so it holds through the evening (when the broker moves to the next begin-of-day file before the open was not observed). Until the closing file is out the begin-of-day file is used. Before the open / intraday: margin is computed on the begin-of-day parameters — the data date's `s` file (identical risk arrays and prices to the next session's i1) — because that is what a broker calculator matched: on 18 Nov 2026 about 12:00 IST, with i2 (11:03) already out, Zerodha's basket margin showed SPAN ₹14,235.50 (net option value ₹5,299.50 at the 17 Nov closes) for the BANKNIFTY 23 Nov 61400/60900 PE · 63200/63700 CE condor and ₹1,26,338 for a naked short NIFTY 25800 CE; the `s` file gives ₹14,235.6 and ₹1,26,338.6, the i02 file ₹14,314 and ₹1,15,271. During the session the latest intraday file is still downloaded (in parallel) for the "if placed now" prices and its SPAN is reported alongside ("NSE's 11:03 IST intraday file … re-computes SPAN at ₹…"); if the begin-of-day file cannot be fetched the margin falls back to the intraday file and says so, XML (CME SPAN format 4.00). For the legs' contracts it sums units × the 16-scenario risk arrays (price ±1/3, ±2/3, ±3/3 of the scan range with volatility up/down, plus two weighted extreme moves; per unit), takes the worst scenario as scanning risk, applies the file's short-option minimum (0 in NSCCL files) and subtracts the net option value: SPAN = max(0, max(scan risk, short-option minimum) − Σ units × option price). Exposure (extreme loss) margin follows NSE Clearing's equity-derivatives margins page: index derivatives 2% of notional, short index options more than 10% out of the money 3%, more than 9 months to expiry 5%; stock derivatives 3.5% (5.25% beyond 30% out of the money); futures at the contract price, short options at the underlying's last close (the bhavcopy close — intraday SPAN files carry an intraday underlying price, which is used for the risk arrays only), long options none; plus 2% on short index options on their expiry day (SEBI circular SEBI/HO/MRD/TPD-1/P/CIR/2024/132, 1 Oct 2024, effective 20 Nov 2024). Printed as "indicative ₹X (SPAN ₹A + exposure ₹B; brokers' figures typically within ±10%; your broker's basket margin is final)". **Expiry-day extra (round 8):** the margin is for an entry day — the session in progress, else the next session (after the close, at a weekend, on a holiday) — and the extra 2% is charged only when that day is the expiry day. It is then printed apart, with the day: "indicative ≈₹80,710 normal (SPAN ₹13,629 + exposure ₹67,082) + ₹67,082 expiry-day extra 2% on short index options (SEBI circular …) = ₹1,47,792 if you enter on Mon 23 Nov (expiry day; the next session, assumed as the entry day); broker calculators show the lower ₹80,710 before that day" (JSON `expiry_extra`, `normal_total`, `entry_day`, `entry_is_today`); the ±10% band is claimed for the normal part only. On Sat 21 Nov 2026 Zerodha showed ₹33,422 (BANKNIFTY 64500/64000 bear put spread) and ₹76,022 (NIFTY 25600/25800/25800/26000 iron fly) for 23 Nov positions — the normal figures — where the round-7 script printed ₹77,562 and ₹1,47,201 with the extra folded in and the ±10% band. Entered before expiry day and held into it, the full report adds "Held into expiry day (Mon 23 Nov), the short index legs add a further 2% exposure that day, ≈₹…" (JSON `extra_if_held`). **Weekend and holiday file:** the next session's begin-of-day file (`nsccl.<next session>.i1`, out the evening before) when published, else the last `s` file. On Sat 21 Nov 2026 Zerodha's SPAN for that iron fly was ₹13,629: the 23 Nov i1 (created 20 Nov 20:55) gives ₹13,628.55, the 20 Nov `s` file ₹13,038.35 and the 20 Nov closing file i5 ₹12,940.20 — the i1 for a later date re-values the risk arrays, so it is not a copy of the `s` file there. During the session the begin-of-day file is now today's i1 first, then the data date's `s` file. **Exposure vs a broker:** the same Zerodha check showed exposure ₹66,844.68 (condor) and ₹31,196.56 (naked NIFTY lot) against 2% × the 17 Nov close × units = ₹74,728 and ₹33,004 (totals ₹81,080 vs ₹88,964, −8.9%; ₹1,57,535 vs ₹1,59,342, −1.1%). The broker's implied base (≈55,704 BANKNIFTY, ≈23,997 NIFTY per unit) matches neither the close nor the live index, and its NIFTY figure was the same ₹31,196.56 per lot on 18 Sep 2026 (NIFTY 23,346) — a broker convention not in NSE Clearing's published rule. Exposure applies to each short leg's notional whether or not a wing hedges it: NSE Clearing's equity-derivatives margins page (https://www.nseindia.com/static/products-services/equity-derivatives-margins) gives an exposure-margin spread benefit only for futures calendar spreads (one third of the far-month value) and says it "is not provided for option contracts", since exposure applies only to short positions and long positions carry none to offset (page text as indexed by a web search on 18 Nov 2026 — the page refuses scripted fetches; no later circular was found that adds an offset for hedged option positions, and NSE commodity-option circulars likewise say no ELM benefit is given for spread positions). So no offset is modelled. **Hedged positions** (a short option with any long leg): exposure is most of the margin there (84% on the condor above), so the broker's lower notional shows up as a larger gap in the total; the result carries `hedged`, `hedged_note` and, for index options, `broker_low` = SPAN + exposure × 0.8833 (Zerodha's exposure ÷ NSE's rule on the condors, lowest seen: 0.894 on 18 Nov, 0.883 on 19 Nov 2026 — Zerodha's ₹66,844.68 per condor did not move while BANKNIFTY rose from 62,273 to 63,063, so the ratio falls as the index rises), printed as "Hedged position: NSE gives no exposure offset for hedged options …, so expect roughly ₹81,081–₹88,964" and in the grid summary as "expect each row's margin up to about 9% lower". A handful of observations, so the range is evidence, not a rule; NSE's rule stays the headline figure and the broker's basket margin is final. **Validation:** on the real 18 Sep 2026 file the method reproduces a published worked example re-run against a live broker SPAN calculator to the paisa for SPAN (short 23400 CE ₹1,33,227.90; short 23300 PE ₹1,30,364.65; short straddle ₹1,36,584.50; bull put ₹17,611.75; long future + put ₹29,138.20; long call and bull call ₹0); exposure is 2% × close × units (₹30,350.32 per short NIFTY lot), where the broker showed ₹31,196.56 (+2.8%) — brokers' exposure base can differ. Not modelled, so the margin says "unavailable" instead: legs on more than one expiry (calendar spread charge), and any file or contract that cannot be read — "margin unavailable — check your broker's basket margin". Stock ad-hoc/surveillance margins and broker add-ons are not included. Return on margin = maximum profit after costs ÷ (SPAN + exposure), if held to expiry; premium for bought legs is paid on top, so for a net debit the payoff prints "Cash needed (margin + premium paid)" — e.g. the NIFTY 25300/25500 bull call spread on 19 Nov 2026: ≈₹33,169 margin (Zerodha ₹31,197) + ₹8,429 premium ≈ ₹41,598, or ≈ ₹38,099 at the hedged broker range. The SPAN file is priced at its own time's levels (i1 = the previous close), so intraday the broker's figure moves with the market.
- **One session to expiry (round 8):** when the selected expiry is at most one session away (counted from today's session while it is open, else the next session, with NSE's holiday list), chain, payoff and grid reports start with "**Expires Mon 23 Nov — 1 session left** (moved from Tue 24 Nov, NSE trading holiday (…)); next expiries: Tue 1 Dec (weekly), Tue 29 Dec (monthly)" (JSON `sessions_left`, `expiry_lead`). The chain summary then shows one figure for the expiry session — "Expected move for the Mon 23 Nov expiry session: 1 SD ±290 (1.12%) — 68% implied range 25,482–26,062 around the forward 25,772" — and drops the separate next-session 1-SD line (the to-expiry variance is that session's, weekend decay included) and the straddle range. Every 68% range is labelled "around the forward" (it is centred on the lognormal median of the forward).
- **Grid:** for each target delta, the traded out-of-the-money call and put with the nearest |delta| are the shorts; the wing is the traded strike nearest to short ± width (the actual width is shown if it differs). Duplicate rows are dropped. Each row is a full `payoff` run, so every figure has the same basis as above.

## Strikes given without an underlying

When the user says only "25800 CE" (or "should I sell the 25800 CE?"), pass the strike as the symbol (`fno.py chain 25800CE --summary`) or give legs without a symbol (`fno.py payoff --leg SELL:CE:25800:1 --summary`). The script reads the latest bhavcopy, keeps the underlyings that list every given strike (indices first, then stocks), and picks the one whose close is nearest by moneyness (smallest |ln(strike ÷ close)|, within 15%). The first lines state the assumption and name the other candidates, e.g. "Underlying assumed: NIFTY — strike 25,800 is 1.6% from NIFTY's Tue 17 Nov close 25,387.40, the nearest by moneyness; also listed on FINNIFTY (28,195, 8.9% away)". The skill should repeat that assumption in the answer and ask the user to name the underlying when a second candidate is plausibly close (a strike between NIFTY and FINNIFTY levels, say). Side and size are never inferred from the strike: "sell" means `SELL:CE:STRIKE:1`, and one lot unless the user said otherwise (state it).

## Limits

End-of-day data is stale during market hours, and the reports say so in their first line; the "If placed now" figures are a model re-price at the live level, not quotes — a live chain and live OI need the user's broker connector (a ceiling for this free script). Margins are indicative from NSE's SPAN parameters (brokers' figures typically within ±10%); the broker's basket margin is final. A `chain` run downloads two bhavcopies (the data date's and the previous trading day's) unless `--no-compare` is given, plus the small holiday, live-level and participant-OI files, and during market hours one ~10 MB SPAN file for the "Now (estimate)" line (`--no-snapshot` skips it). **Previous day:** the comparison day comes from NSE's holiday calendar (weekdays only if it does not load). A missing previous file — bhavcopy or participant OI — is tried twice; if it is still missing the comparison uses the last earlier file and is labelled: "Mon 16 Nov bhavcopy unavailable (tried twice); compared with Fri 13 Nov instead (2 sessions)", changes read "vs 2026-11-13, 2 sessions" / "since Fri 13 Nov (2 sessions)", never "on the day", and the summary's ⚠ line lists the gap (on 18 Nov 2026 a silent fall-back to 13 Nov turned the PCR change from +0.02 to −0.05 and FII put change from +66,399 to −17,452). When the selected symbol's own option expiry with open interest falls inside the window (for example NIFTY's 17 Nov weekly in a 16→17 Nov NIFTY comparison), the ⚠ line adds that much of the option OI change is expiring contracts closing or rolling. Participant OI covers every index, so any index expiry in its window is noted on the "Who holds index F&O" line instead (a BANKNIFTY chain no longer shows a chain-level warning about NIFTY's expiry). Implied probabilities describe what option prices imply under a simple model, not what will happen. IV and Greeks depend on the rate assumption and on closing prices that may come from thin trades; the smile fit inherits that noise (its fit error is printed). PCR, max pain, OI walls and participant OI describe positioning and have weak predictive value. Payoff charges come from an example rate card; slippage is excluded. For the exact margin use the user's broker basket margin; see [basket margins](basket-margin-providers.md). Nothing here authorizes an order.
