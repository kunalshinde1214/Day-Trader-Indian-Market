# market

Read the [core skill](../../SKILL.md) first. Resolve scripts relative to `${CLAUDE_PLUGIN_ROOT}`. Run them with `python`; if that is not found use `python3` (macOS/Linux) or `py` (Windows). Keep user files outside the plugin folder, and pass the user's words as arguments, never as raw shell text.

Routes: `python "${CLAUDE_PLUGIN_ROOT}/scripts/daily.py" india-daily --collect-public` for all three indices, or `nifty`, `sensex`, `banknifty` for one. Pass the name without a leading slash ([daily reports](../../references/daily.md)).

For a specified closing-report date, use `--collect-close --session YYYY-MM-DD` instead. Read [closing context](../../references/closing-context.md) and keep source dates and stale context explicit.

Use --collect-kite or --input for configured sourced inputs. Show feed age, calendar basis and missing coverage. Never substitute --demo for unavailable real data or infer an executable contract from index levels.

During market hours and after the close the daily reports add two dated, filtered news lines: "Possible reasons (headlines, unverified)" (up to three headlines on today's biggest movers or the market, those giving a cause first) and "Cues" (GIFT Nifty, US markets, gold, crude, rupee). Use them for the "why", always as possible causes with their dates and publishers; if they say "a gap", the search failed - say so. After the close the Cues line looks ahead to the next session (GIFT Nifty evening, US markets, crude, gold, rupee); present it as what to watch before the next open, and "none yet" as no fresh headline, not as calm.

Then search the web for what the script does not collect: overnight global cues, GIFT Nifty, FII/DII flows, RBI/SEBI or macro events today, and the main reasons the index moved. Generic web searches often return the same calendar date from earlier years, so put the full date with the year in the query (for example `stock market today 18 November 2026`), check each article's own date and drop anything not from today; if nothing dated today turns up, fall back to the script's dated headlines. Cite each source with its date and keep it apart from the script's numbers ([web research](../../references/web-research.md)).

## "Why did the market move?"

Run `python "${CLAUDE_PLUGIN_ROOT}/scripts/market_movers.py" --summary` (add `--premise up` or `--premise down` with the user's claim, or `--session YYYY-MM-DD` for a past day). It states the actual direction first (after 15:30 IST as "closed up/down"), so correct a wrong premise before explaining. It gives sector moves, breadth, the stocks that added or took away the most index points (estimated weights anchored to the latest NSE Indices Nifty 50 factsheet's top-10 and sector weights in `assets/index_weights.json`, with the check against the actual move; always call these points estimated), a broader-market line (Midcap 150, Smallcap 250, Nifty 500 advances/declines), VIX and the previous session's FII/DII. Treat its headlines as possible causes, not verified ones; add dated news from the web for the reasons, and keep the two apart. The script keeps only headlines that name a moving stock or sector, or a macro/flow driver (FIIs, the Fed, crude, the rupee, Wall Street, gold, RBI, inflation, profit booking), published since the last close; stock news dated to an earlier day, corporate housekeeping (ESOP grants, AGM/EGM or board-meeting notices) and multi-day stories that run against today's move are dropped, and headlines that give a cause ("falls as gold prices crash") come first.

If a report prints "⚠ stock contributions not collected — rerun", NSE refused a download this run (usually the previous-day bhavcopy); run the same command once more before answering, and if the line is still there, answer from the sectors and say the stock-level drivers are missing.

On a weekend or NSE holiday every market_movers.py report (the summary, `--sector`, `--period`) and every daily report starts "Market closed today (<day date>: <reason>) — figures are from the last session, <date>." Lead with that line, then answer for the last session with its date. The headline searches then cover the news since the session before the last one (evening wrap-ups of that earlier session are left out). If a report says "Headlines not collected (reason)", the search did not run or failed: say so and search the web with the session's date.

## One sector: "Nifty IT aaj kaisa raha? Kaun se stocks gire?", "Why did metal stocks fall?"

Run `python "${CLAUDE_PLUGIN_ROOT}/scripts/market_movers.py" --sector IT --summary` (several words work with or without quotes, e.g. `--sector metal stocks`; sector names: IT, BANK, PSU BANK, PRIVATE BANK, FINANCIAL SERVICES, AUTO, PHARMA, HEALTHCARE, FMCG, METAL, REALTY, ENERGY, OIL & GAS, MEDIA, CONSUMER DURABLES; natural names such as "Nifty IT", "IT stocks", "metal stocks", "PSU banks" or "real estate" also work; add `--session YYYY-MM-DD` for a past day). It gives the sector index's change and its rank among NSE's sector indices, every constituent's % change (from NSE's official bhavcopy once published, otherwise Yahoo's last price against NSE's previous-day close, which the line names), advances/declines, and dated Google News headlines that may explain the move (sector stories first, then the commodity or driver behind it, such as copper for metals, then the biggest movers' own news). Answer with the sector's move and the stocks that fell (or rose) most, then the possible causes as unverified headlines with publisher and time. If the user's premise is wrong ("why did metal stocks fall" on a day the sector closed up), lead with the correction - the sector's actual direction and how many of its stocks rose - before anything else. The full report (without `--summary`) has the constituent table.

## Over a period: "How did midcaps and smallcaps do this week compared with the Nifty?"

Run `python "${CLAUDE_PLUGIN_ROOT}/scripts/market_movers.py" --period week --summary` (`month`, `ytd`, or `--since YYYY-MM-DD` for a change since that day's close). When the user names indices, add them with `--indices` (for example `--indices midcaps smallcaps`, `--indices bank IT`, `--indices next 50 sensex`) and the answer leads with those, each with its gap to Nifty 50 in percentage points; without it the answer leads with Nifty 50. It compares Nifty 50, Bank Nifty, Next 50, Midcap 150, Smallcap 250, Nifty 500 (and Midcap/Smallcap 100) and every sector index over the period from NSE's official daily index files, with each index's gap to Nifty 50 in percentage points. "This week" means since the previous week's last close (normally Friday's); the output names both dates and whether the end is an official close or a live level. Quote the dates with the figures.

## Market mood, "overheated" or "stretched" questions

Run `python "${CLAUDE_PLUGIN_ROOT}/scripts/market_movers.py" --summary` once, with no other flags (add `--premise` or `--flow-premise` only when the user states a direction or an FII claim). Besides the day's move, every summary carries the context for mood questions: breadth (Nifty 50, Nifty 500 advances/declines and all NSE shares from the bhavcopy), India VIX, NSE's FII/DII and NSDL's month-to-date FPI flows, and a "Mood context" line - Nifty 50 P/E, P/B and dividend yield from NSE's daily index file against their own range over the past year (NSE's month-end files), the Nifty 50 change over one month, and India VIX against its 52-week range. Present these as where things stand compared with their own recent history, never as a call that the market will fall or rise, and never as advice; say which figures are high or low within their ranges and that valuations can stay high or low for long periods.

## Market mood and FII flows: "Market mood kharab hai - FII selling?"

Run `python "${CLAUDE_PLUGIN_ROOT}/scripts/market_movers.py" --summary --flow-premise selling` (or `buying`, matching the user's claim). Besides the direction, sectors, breadth and VIX, it prints NSE's latest provisional FII/DII figures and NSDL's month-to-date FPI equity flows with the last five reports (the NSDL line is in every summary; if it says "not collected", NSDL's page failed this run). When the user's premise is wrong the line starts "Correction: FIIs were net buyers, not sellers"; lead your answer with that correction, then explain what did drive the day. Use `--premise up|down` the same way for a wrong direction. NSE serves FII/DII for the latest day only; NSDL's figures lag by a day and differ from NSE's provisional ones, so name each source and date.

Sensex comes from Yahoo and can be about 15 minutes behind (BSE does not serve scripts). During market hours the Sensex and india-daily reports give ONE Sensex figure: "Sensex ≈ X (y%) at HH:MM IST (estimate from live Nifty 50); last Yahoo quote Z at HH:MM IST" - the latest Sensex quote (or shared 5-minute bar) moved by the live NSE Nifty 50 change since then, scaled by the Sensex/Nifty ratio fitted on today's bars (the "Estimated Sensex now" data note explains it; the like-for-like 5-minute-bar comparison is in the data notes). Quote it the same way (for example "Sensex ≈ 81,890, estimated from live Nifty 50 at 13:17 IST; last Yahoo quote 81,897 at 13:03 IST"), never as a BSE figure, and do not add a second Sensex percentage. A web lookup is optional: at most one search, `Sensex today <date> live` (for example `Sensex today 18 Nov 2026 live`); if the first result does not give a level with a time from today, stop and use the estimate. Do not try site after site (BSE, Google Finance, Moneycontrol, ET and Business Standard block scripted fetches).

Research and paper workflows only. Missing data is a gap, not an all-clear. Nothing here places an order.
