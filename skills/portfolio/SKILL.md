# portfolio

Read the [core skill](../../SKILL.md) first. Resolve scripts relative to `${CLAUDE_PLUGIN_ROOT}`. Run them with `python`; if that is not found use `python3` (macOS/Linux) or `py` (Windows). Keep user files outside the plugin folder, and pass the user's words as arguments, never as raw shell text.

Primary route: `python "${CLAUDE_PLUGIN_ROOT}/scripts/holdings_review.py" --input FILE [--tradebook FILE] [--fy 2026-27]`. Start with `--summary` for a short answer-first digest. Add `--format json` when you need exact numbers, `--no-prices` when offline. Input formats, method, rates and limits are in [holdings review](../../references/holdings-review.md).

How to answer:

1. Get the holdings. If the user has a broker connector connected (Kite, Upstox or another), read holdings there and write a `holdings_v1` JSON file outside the plugin folder; never place, modify or cancel orders through the connector. Otherwise use the file they give (Zerodha Console holdings CSV or tradebook CSV) or build `holdings_v1` from pasted data. When the user mentions when they bought, add `"bought": "2024-03-15"` (or just the month, `"2024-03"`) to that holding; it becomes a tax lot and lets bonuses and splits be applied. For tax questions, ask for a tradebook or purchase dates; a holdings file alone has none.
2. Run the script once and answer the user's actual question first, in plain language, using the report's numbers. Show the dates: the holdings date, the price date and the financial year. Show the full report only if they asked for a full review.
3. Bonuses and splits: the script applies Yahoo's split events to dated holdings and lots, and puts a ⚠ on any holding it could not adjust. Yahoo does not say whether an event was a bonus or a split, and Indian tax treats them differently (bonus shares have nil cost and are held from the allotment date). The summary lists every applied one on a "Bonus applied" (or "Split applied") line, e.g. "HDFCBANK 100 → 200 (1:1, Aug 2025)": say so when you quote the holding, since the share count differs from what the user typed. When a ⚠ or an "adjusted for" note mentions one, check the web (exchange filing or company announcement) and rerun with `--bonus SYMBOL` if it was a bonus. Demergers on the skill's curated list (for example ITC → ITC Hotels, Reliance → Jio Financial) are flagged with ⚠ and the new shares the user should hold; quote those numbers, and rerun with `--apply-demergers` if the user wants the published cost split applied. For a demerger not on the list, check the web. A listed bonus or split dated before the purchase is named "not applied" ("WIPRO 1:1 bonus Dec 2024 predates purchase"): the typed quantity and price are already after it, so say that rather than suggesting an adjustment.
4. Say clearly which holdings show "price unavailable" (the script has already retried them once). When the summary says "excludes X (price unavailable), not a full figure" on the P&L, return or tax line, repeat those words; never present such a figure, including a ₹0 tax, as complete. Flag every item under "Data gaps and notes", including lot/holding quantity mismatches and unmatched sells.
5. Concentration: give the largest-holding weight, top-5 weight, Herfindahl reading and the largest sector. Describe it; do not tell the user to rebalance, buy or sell.
6. Tax: call every figure an estimate. From 1 April 2026 the Income-tax Act 2025 applies ("tax year", sections 196 and 198, same 20% / 12.5% rates); the report uses the right law for each sale date. Quote the annualised return against the Nifty 50 over the same dates when the user asks how they are doing, and the value of demerged shares they may still hold. The "if you sold everything" line ends with the unrealised gain by term ("all ₹22,404 long-term", or long-term and short-term amounts): use it for "how much is long-term". The "⚠ N items to check" count includes every flagged price ("SBIN ×2" when two of its typed prices are flagged) and fully sold symbols with a flagged price. When purchase dates are missing the "if sold today" figure is a range; give both ends, say which dates would narrow it, and ask for them. When a typed buy price is outside what traded then (⚠), the P&L, return per year, best/worst and tax all rest on it: quote the summary's ⚠ line under the value ("⚠ ITC and SBIN typed prices are outside what traded then; at ITC ~₹428 … and SBIN ~₹961 …: P&L −₹15,469 (−7.1%), return per year −1.7%" — every ⚠ price, combined) next to the headline, and the tax what-if under the "if you sold everything" line, which swaps only the prices that change the tax and says so; say when the what-if flips the P&L's sign, and ask the user to check the prices. When a demerger on the list applies to dated shares, the summary's tax figure and "net long-term loss left over" use the published demerger cost split, which Indian tax law requires (s.49(2C)/(2D) of the 1961 Act, carried into the Income-tax Act 2025); quote that figure first and the full-typed-cost one only as the labelled second figure, and say it assumes the typed price is what the user paid before the demerger. Mention a "net long-term loss left over" as information: it cannot reduce short-term gains and can be carried forward against long-term gains if the return is filed on time. Say the rates are labelled defaults that must be verified, that cess is shown separately, and list what is not modelled when it could matter (surcharge, grandfathering for pre-1 Feb 2018 shares, demergers, loss carry-forward, intraday/F&O). The "LTCG exemption remaining" and the hypothetical "if sold today" line are for information only. When that estimate is ₹0 the script says why in brackets (losses set off, the long-term gain within the ₹1.25 lakh exemption); pass that reason on with the figure. Never phrase anything as a recommendation to sell, book profits or harvest losses; say "for information; check with a tax professional".
7. For current tax rules, budget changes, or anything not modelled, use web research ([web research](../../references/web-research.md)): prefer incometaxindia.gov.in, the Finance Act text and CBDT circulars, cite source and date, and keep web facts apart from the script's numbers.
8. If the user asks whether to buy, sell or hold something, explain what the data shows and that the decision is theirs; this tool is not investment or tax advice.

Research and paper workflows only. Missing data is a gap, not an all-clear. Nothing here places an order.
