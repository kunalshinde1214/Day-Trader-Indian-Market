# Release status — 10 November 2026

Version: **0.9.5-five-broker-carry-alpha**. Adds fifteen Claude plugin skills, credential-free public research, index collection, multi-tag screening, one-minute/custom-level entry research, flexible exits, news discovery and supplied XBRL analysis. Includes limited five-broker carry collection, streaming, monitoring deployment files, daily commands, paper analysis and human-operated execution. Live starts disabled. This is **not the completed production specification**. No authenticated broker account was connected, real order submitted, webhook delivered or production monitoring service activated during development.

User-owned broker setup and read-only acceptance are documented; a developer brokerage account is not required for public distribution.

## Four remaining full-product workstreams

These items are not hidden behind a completion percentage:

1. **Broker/data acceptance:** authenticated checks on five target brokers, including actual trade-book shapes, units/timestamps, fees, index history, empty/partial responses, entitlements and emergency controls. Requires user-controlled authorized environments. Credentials remain local; the agent does not place acceptance trades.
2. **Complete automatic production data:** exchange calendars/surveillance/F&O membership, complete filings/attachments, verified constituent membership and closing breadth, released FII/DII/GIFT data and historical corporate-action/membership reconstruction. Current optional constituent/news collection covers only its documented sources; provider availability, effective dates and complete coverage remain unresolved.
3. **Advanced production operations:** ambiguous Angel/FYERS field conventions, unsupported T1/pledged/MTF inventory, corporate-action/settlement adjustments and mixed-account risk/execution integration; OS activation/runtime acceptance; real webhook-receiver acceptance; and any required broker-hosted approval integration. Limited five-broker carry collection, five-broker streaming, deployment files, canonical carry accounting, supervision, trade imports and fee/notification code are implemented. Stops/exits still need individual human actions; unattended protection/auto-flatten is not implemented.
4. **Production release acceptance:** account-specific cost/exemption and provider/data-rights review, licensing authority and applicable broker/exchange operating requirements. Public alpha distribution is separate from this acceptance; verify its commit, Actions and release artifacts in the [chosen repository](https://github.com/kunalshinde1214/Day-Trader-Indian-Market). Files retain MIT attribution and the source-available personal-use license. No activation server, subscription purchase, global install or tax engine is included.

The supplied proposal also discusses advanced replay, slippage/liquidity, options and portfolio margin. The current replay conditions on an observed entry and does not claim those research models. Do not advertise this alpha as unattended live automation, a complete exchange-data platform, a tested broker connection or a proven strategy.

## Package and use

```text
python scripts/release.py --out dist/india-day-trader-0.9.5-five-broker-carry-alpha.zip
```

The command runs tests before producing the archive and refuses to overwrite an existing ZIP. Its manifest lists daily commands, canonical accounting plus five limited broker collectors requiring reviewed opening evidence, five-broker streaming adapters, render-only deployment, packaged hashes, live disabled by default, and full-spec/authenticated completion false. Earlier archives remain historical checkpoints. Unpack the single skill folder and run a labelled demo first. Distribute only with the alpha scope and acceptance limits stated clearly. A whole-product completion percentage would conceal outstanding engineering and external acceptance requirements; use the explicit counts above.
