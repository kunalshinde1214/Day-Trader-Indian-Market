# fno

Read the [core skill](../../SKILL.md) first. Resolve scripts relative to `${CLAUDE_PLUGIN_ROOT}`. Run them with `python`; if that is not found use `python3` (macOS/Linux) or `py` (Windows). Keep user files outside the plugin folder, and pass the user's words as arguments, never as raw shell text.

Routes ([details](../../references/fno.md)):

- Chain and positioning: `python "${CLAUDE_PLUGIN_ROOT}/scripts/fno.py" chain NIFTY [--expiry YYYY-MM-DD] [--strikes 12]`
- Expiry list: `python "${CLAUDE_PLUGIN_ROOT}/scripts/fno.py" expiries BANKNIFTY`
- Strategy payoff: `python "${CLAUDE_PLUGIN_ROOT}/scripts/fno.py" payoff NIFTY --leg SELL:CE:25800:1 --leg BUY:CE:26000:1 [--chart PATH.svg]`. Leg format is `SIDE:TYPE:STRIKE:LOTS[:PREMIUM]`; futures are `BUY:FUT::1`. When the user describes strikes relative to the money, pass them as written and let the script resolve them in the same command: `ATM` is the listed strike nearest spot (the live or closing level the report quotes), `ATM-1` / `ATM+2` count strike steps, a second number is points (`ATM-1-500` = one step below ATM, then 500 points lower) and `ATM-200PTS` is points from ATM. A bear put spread one strike below ATM, 500 wide, is `payoff BANKNIFTY --leg BUY:PE:ATM-1:1 --leg SELL:PE:ATM-1-500:1 --summary`; an iron fly with 200-point wings is `--leg SELL:CE:ATM:1 --leg SELL:PE:ATM:1 --leg BUY:CE:ATM+200PTS:1 --leg BUY:PE:ATM-200PTS:1`. The report's first lines say what ATM and each relative strike resolved to ("**Strikes:** ATM 64,600 = the strike nearest spot …"); repeat them. A plain number after ATM is strike steps, never points; a leg that resolves to an unlisted strike stops with the nearest listed ones.
- Iron fly without a width: `python "${CLAUDE_PLUGIN_ROOT}/scripts/fno.py" grid NIFTY --structure fly --summary` sells the ATM call and put and lists one row per wing width (defaults NIFTY 100/150/200/300, BANKNIFTY 300/500/700/1000, FINNIFTY 100/150/200/300, MIDCPNIFTY 50/75/100/150 points, stocks 2/3/4/6 strike steps; `--width N` for one width); `--row N --summary` gives that row's payoff.
- Strike comparison when the user gives no strikes: `python "${CLAUDE_PLUGIN_ROOT}/scripts/fno.py" grid BANKNIFTY --structure condor|strangle|spread [--width 500] [--monthly]` (wing width defaults to NIFTY 100, BANKNIFTY 500, FINNIFTY 100, MIDCPNIFTY 50 points, stocks two strike steps; the header says when the default was used, so tell the user they can change it) lists short strikes from delta 0.35 to 0.05 with credit and maximum loss after costs, breakevens, probability of profit and chance of maximum loss, plus indicative margin, return on margin and P&L at expiry at ±1 and ±2 SD. Add `--summary` for a compact eight-column table (#, strikes, credit, max loss, breakevens, profit chance, P&L at −1 / +1 SD at expiry, margin) that fits a chat reply. Show it and let the user choose; never pick a row. Rows are picked by delta at the last close; during market hours each short leg shows its delta now (Δ) and a ⚠ line names any row whose short strike is now within 0.5% of the live level ("short put now near the money"), so repeat that warning. When the user asks for a "payoff" without strikes, show this grid with its breakevens and, in the same reply, offer `--row N --summary --chart PATH.svg` for the payoff and chart of any row. When the user picks one, run the same command with `--row N [--summary] [--chart PATH.svg]` for that row's full payoff (rows are fixed for the day).
- Margin: payoff and grid download NSE Clearing's SPAN files (about 10 MB each) for an indicative SPAN + exposure margin, computed on the SPAN file broker calculators use at that time of day — the begin-of-day file before the open and during the session, today's closing intraday file after the 15:30 close (Zerodha's calculator matched it to the rupee on 19 Nov 2026) — with exposure on the latest close; at a weekend or on a holiday it uses the next session's begin-of-day file (Zerodha's calculator matched it on Sat 21 Nov 2026). It prints with a band ("brokers' figures typically within ±10%; your broker's basket margin is final"). On hedged positions (spreads, condors, flies) the script adds that NSE gives no exposure offset for hedges but broker calculators have charged less exposure (Zerodha's exposure per lot stays fixed while the index moves: 9–14% lower on Bank Nifty spreads on 18–21 Nov 2026) and prints the resulting range instead of the ±10% band; quote that range, not a single figure. Expiry day: when the entry day the margin assumes is the expiry day (the session in progress, or the next session when run after the close, at a weekend or on a holiday) short index options pay a further 2% exposure (SEBI circular SEBI/HO/MRD/TPD-1/P/CIR/2024/132), and the script prints the two parts ("≈₹80,710 normal + ₹67,082 expiry-day extra 2% = ₹1,47,792 if you enter on Mon 23 Nov (expiry day)"). Quote both parts and the day, and say broker calculators show only the normal figure before that day — never present the total as what the broker shows today. Entered earlier and held into expiry day, the full report notes the extra 2% charged that day. For a net debit (spreads paid for, bought options) the payoff also prints "Cash needed ≈ margin + premium paid": quote that as the money the trade ties up, not the margin alone. Add `--no-margin` to skip it when the user does not need margin or the connection is slow.
- A bare strike works: `fno.py payoff --leg SELL:CE:25800:1` infers the underlying from moneyness and states the assumption; repeat that assumption to the user.
- After the close (15:30 IST) and before the evening bhavcopy (usually ~18:00–19:00 IST) the last bhavcopy is a day old, and the scripts say so in a bold first line. The chain then reads NSE's option chain at today's close ("NSE option chain, 18 Nov 15:30 close") for PCR, OI walls, max pain and OI change; if NSE's chain is unavailable or rejected it falls back to the previous bhavcopy, says "today's bhavcopy not yet published … re-run after that" and prints the reason on a second bold line ("NSE's option chain at today's close was not used: …") — pass that reason on. The OI walls are labelled against the level quoted now ("Call OI walls above the NSE close 63,063"), so a wall the index has passed is not called resistance above spot. The 'now' prices after the close are NSE Clearing's closing prices; the bhavcopy close can differ slightly (on 18 Nov 2026 near-the-money strikes were typically within ±1–2%, either way). Payoff and grid keep the "If placed now (estimate)" column, the short legs' Δ and the ⚠ near-the-money warning, priced at today's NSE closing level from NSE Clearing's closing snapshot, with the previous close as reference. Quote the source label, offer to re-run after ~19:00 IST for the official figures, and mention any scheduled event before the next open (results, RBI, global data) found by a web check. For a single short option whose price has moved a lot, lead with the script's "Selling now would get about ₹X (estimate)" line, not the stale close premium.
- One session to expiry: when the selected expiry is the next session (or today's), chain, payoff and grid start with a bold line such as "**Expires Mon 23 Nov — 1 session left** (moved from Tue 24 Nov, NSE trading holiday (…)); next expiries: Tue 1 Dec (weekly), Tue 29 Dec (monthly)". Lead with it, and offer the next weekly or monthly with `--expiry` when the user may want more time. The chain summary then gives one 1-SD figure for the expiry session (68% range around the forward) instead of separate next-session, to-expiry and straddle ranges.
- Add `--summary` to any command for a short answer-first digest; use the full report when the user wants the strike table or the payoff table. During market hours the chain shows a "Now (estimate)" line (ATM IV, straddle and ATM premiums from NSE Clearing's intraday snapshot at the live level); `--no-snapshot` skips that 10 MB download.

The chain report compares PCR, max pain, ATM IV and OI with the previous trading day (from NSE's holiday calendar); use that change when the user asks "what changed" or which way positioning is moving. The chain summary ends with a **Next session** block: the 1-SD range to the next session's close (from the live level at the now ATM IV during market hours) and the OI walls near spot. Max pain is given as a distance from the close and from the live level, and the straddle as a multiple of the 1-SD move (≈ 0.8 SD is normal). If the summary's ⚠ line says a previous-day file was unavailable, the change spans more than one session: say so ("since Fri 13 Nov, 2 sessions"), never "on the day". If it says the chosen symbol's own options expired inside the window, warn that much of its OI change is expiring contracts closing or rolling; a caveat on the "Who holds index F&O" line about another index's expiry applies to the participant figures only. The summary shows that participant line only when FIIs are one-sided in index futures (≤25% or ≥75% long) and India VIX's 1-year percentile only when it is in the top or bottom 10%; both are always in the full report. During market hours the summary's "Expected move to expiry" line is centred on the live level with the snapshot IV and says so; quote it with that label, never a range centred on yesterday's close as if it were current. The payoff report gives the value at expiry and today (T+0), and the probability of profit and of finishing above each breakeven implied by option prices. Call those probabilities what they are: implied by today's option prices, not a forecast.

How to answer:

1. Map names to NSE symbols (Bank Nifty → BANKNIFTY, Fin Nifty → FINNIFTY, Reliance → RELIANCE). Stocks only work if they are in the F&O segment.
2. Check the expiry the user means. Bank Nifty, Fin Nifty and Midcap Nifty have had no weekly options since November 2024 (only monthly); the report labels each expiry weekly or monthly and flags one moved for a holiday — from NSE's holiday list when it has it (an expiry on the last trading day before a holiday on the regular expiry weekday was moved from that holiday), and the regular weekday is Tuesday for every NSE expiry since Sep 2025. If the user asks for a "weekly" that does not exist, say so and offer the nearest monthly.
3. During market hours the report's first line says the chain is end-of-day; keep that line in your answer. For "kal kya lagta hai", use the dated tomorrow range from the live level, never the range for today's running session. The free data is NSE's **end-of-day** file, so say which trading day it is from. During market hours, if the user has a broker connector with an option chain (for example Kite or Dhan), read the chain there, save it as an `fno_chain_v1` file ([format](../../references/fno.md)) and pass `--input`. Without a connector, say the numbers are from the last close, state how far the index has moved since that close (the summary's live level and % change), and tell the user the live chain is on NSE's option-chain page (nseindia.com, Option Chain) or in their broker app.
4. Answer the question first. For next-session levels quote the "OI walls near spot" line (largest OI inside the 1-SD range to expiry) and the max-pain distance from spot; the "biggest overall" walls are often several percent away. PCR, max pain, OI walls and build-up describe where option positions sit; present them as positioning, never as a forecast or signal. Give both readings when they conflict.
5. For strategy questions, build the legs the user describes. If they give no strikes, run the grid and let them choose, or ask for the strikes; never choose for them. Then report net premium, maximum profit and loss, breakevens and position Greeks, and offer the SVG chart. Say clearly when a loss is unlimited. During market hours lead with the report's "If placed now (estimate)" column (re-priced from NSE Clearing's latest intraday snapshot, or the close's IVs, at the live index level) and keep the close column as the reference; say the now-price is an estimate, not a bid/ask quote. "Already in this trade from the close?" (model P&L now of legs taken at the last close) is in the full report, and in the summary only with `--held`; add `--held` when the user says they already hold the position. Maximum loss after costs is the worst expiry level shown (it includes the exit STT on in-the-money legs), so it is never smaller than the ±SD rows. Margin: quote the script's indicative SPAN-based margin only with its label, and say the broker's basket margin is the authority; never invent a margin figure yourself.
6. Never recommend a specific trade, strike or position size, and never call any strategy safe. If asked "should I sell this", explain the payoff, the risk and the assumptions, and leave the decision to the user. Selling options can lose far more than the premium received.
7. For events that move options (results dates, RBI policy, budget, expiry-day rules, lot-size or F&O-list changes), check the web and cite the source and date ([web research](../../references/web-research.md)).

Research and paper workflows only. Missing data is a gap, not an all-clear. Nothing here places an order.
